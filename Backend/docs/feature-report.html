A rule-based price-tracking system for noon.com — no AI, no ML, every decision it makes is a plain threshold you could check by hand. This is the full ledger of what shipped: the crawler, the detection logic, the API, the notification loop, and the interface, in the order a request actually moves through them.

01 · data collection noonscraper.crawler

The only part of the system that ever opens a browser. Runs headful — Chrome, not headless — because the target site's Akamai Bot Manager hard-blocks headless at the network layer, not the page layer.

Category crawling shipped Sweeps 5 tracked categories daily, reading price/stock/discount straight off each listing tile.
Detail-page scraping shipped Parses the schema.org Product JSON-LD block on user-submitted pages — name, SKU, rating, live stock status, seller name.
URL normalization shipped Strips Noon's per-session tracking query string before dedup — fixed a real bug that was silently splitting one product into ten rows.
Stealth scraping layer shipped navigator.webdriver, chrome.runtime, plugin/language fingerprints, and launch flags — enough to pass Akamai's static checks headful.
Cross-merchant offer scraper shipped Expands the "other sellers" panel and reads every competing offer, falling back to the single default listing when there's only one seller.
02 · detection & intelligence noonscraper.data

Rule-based on purpose — threshold logic over price history, nothing probabilistic. Every flag this system raises can be explained in one sentence.

Restock detection rule-based Fires when a product's prior snapshot was out-of-stock and the new one isn't. Persisted as a RestockEvent, not just a log line.
Fake-discount detection rule-based Flags a "discount" when the price recently spiked ≥10% above its historical low and the sale price still doesn't beat that low — the % off is measured against an inflated "before" price.
03 · api noonscraper.api

A plain ASP.NET Core Web API — no Chrome, no Docker requirement of its own. Every scrape happens elsewhere; this just reads Postgres and, for check-now, hands the job off.

GET /products shipped List + category filter, each row carrying its latest price, stock, and discount.
GET /products/{id}/history shipped Full snapshot history for one product, oldest to newest.
GET /products/{id}/discount-flags · /restocks shipped Every fake-discount flag and restock event on record for that product.
POST /products shipped Submit any noon.com URL to track — validated, normalized, deduped, filled in by the next crawl.
POST /products/{id}/check-now shipped Dispatches a repository_dispatch event to GitHub Actions rather than scraping in-process — the API needs no browser of its own, which is what let it run on a free host at all. Client polls GET .../check-now/{requestId} for the result.
04 · notifications telegram

A bot can't message someone who hasn't messaged it first — so subscribing runs through a Telegram deep link, not a form, and the platform itself hands over the chat ID.

Subscribe via deep link live t.me/<bot>?start=<productId> → Telegram sends /start <id> the moment Start is tapped → webhook creates the subscription, baselined to the current price.
Restock & price-drop alerts live Fired from the crawler, the only place that ever learns a price actually changed — covers both the scheduled crawl and check-now.
/stop to unsubscribe live Removes every subscription for that chat. No per-product toggle in the UI — there's no way to know whose browser is asking without account linking.
Verified against the real webhook, not a simulation — a live /start click produced an actual row in the database through the registered Telegram endpoint.
05 · interface vite · react · typescript

Built in the same voice as this report — a monospace ledger, not a dashboard of cards. The price history reads as a changelog, not a chart: what changed, and what it changed from.

Item ledger shipped Every tracked product as a row — price, status, last crawled — sortable by any of the three, filterable by category, searchable by name.
Price history log shipped Each crawl as one line: time, price, and ↓/↑/→ against the reading before it.
Cross-merchant check panel shipped Triggers check-now and polls to completion in place, surfacing every seller's price the moment the scrape lands.
Responsive down to one column shipped The item table collapses to stacked rows below the sm breakpoint rather than compressing four columns into a phone screen.
